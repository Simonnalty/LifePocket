# 可行性研究：AI 记账 与 AI 陪伴助手

> 日期：2026-11-20 · 结论先行：**三项均可行**（AI 记账 / AI 待办拆解 / AI 陪伴），
> 无需原生 SDK，纯 HTTP 即可落地，三者共用同一 LLM 接入层；
> 「免费的豆包」实为「有赠送额度的付费 API」，长期免费建议首选 GLM-4-Flash，接口按可切换 Provider 设计，随时可换豆包。
>
> **用户确认的形态（2026-11-20）**：AI 记账 MVP 以**文本输入**为主——输入一段话，
> AI 识别关键词、自动分好类、写好备注并记上账；语音识别作为后续可选增强（见 1.3）。

## 一、AI 语音记账（说话 → 自动分类、备注、记账）

### 1.1 链路

```
麦克风 → 系统 SpeechRecognizer（免费，国产手机普遍本地识别）
       → 文本："今天午饭和奶茶花了三十五块六"
       → LLM 结构化抽取（要求输出严格 JSON）
       → {type:支出, amount:3560分, category:吃, sub:午饭+奶茶, note:原文摘要}
       → 校验（大类必须在本地分类表内，金额正则复核）
       → Room 落库（小类不存在则自动创建）
```

### 1.2 关键设计

- **JSON 约束**：System Prompt 固定 schema，`temperature=0`，解析失败重试一次，再失败降级为手动记账并保留原文进备注。
- **大类锚定**：把本地分类表（吃/穿/住/行/学习…含 emoji）注入 Prompt，LLM 只能从中选；选不出归「其他」。
- **金额防线**：LLM 输出单位为「分」的整数；客户端用正则从原话再抽一遍金额交叉核对，不一致时以原话为准并提示确认。
- **成本**：每条记账约 200~500 tokens，免费额度足够日均几十条。

### 1.3 语音识别选项

| 方案 | 成本 | 说明 |
|---|---|---|
| Android `SpeechRecognizer` | 免费 | 走厂商引擎（小米/华为等中文识别质量好），部分机型离线；**首选** |
| 讯飞开放平台 | 免费额度 | 质量高，但要注册+SDK |
| 豆包/云端 ASR | 付费 | 暂不需要 |

## 一点五、AI 待办拆解（2026-11-20 增补，用户需求）

- **输入**：一大段文字（如整段搬家计划、学习计划、项目清单）。
- **LLM 输出严格 JSON**：
  ```json
  [{"group":"装修布置新家","items":["量房","选装修公司","定预算"]},
   {"group":"英语备考12月","items":["背完list1-5","每周一套真题"]}]
  ```
- **落库**：逐条 `TaskGroup.insert` + `TaskItem.insert`（复用现有 DAO，小任务 sort 顺序即 JSON 顺序）；创建完成回主页展示，可撤销（按批记录 ids，支持一键撤销整批）。
- **防错**：group 名去重（同名追加到现有任务）；单批上限（如 10 组 × 20 条）；JSON 解析失败重试一次。
- 与 AI 记账共用同一 `LlmClient` 和 Provider 配置，只是换 System Prompt。

## 二、AI 陪伴助手（自定义命名 + 情绪价值对话）- **命名与人设**：设置页加「给 TA 起名」，名称存 SharedPreferences，拼进 System Prompt 人设模板（名字、语气、称呼习惯）。
- **对话页**：普通聊天 UI；上下文 = 人设 + 最近 N 轮对话 + 可选注入账目摘要（「这周花了 ¥xx，吃占 60%」），让 TA 能聊生活也能聊钱。
- **情绪价值**：来自人设 Prompt（共情式回复、鼓励、轻幽默），模型层面免费档已足够；不承诺心理治疗作用，极端情绪关键词给一句温和提示即可。
- **输出方式**：MVP 先一次性返回（实现最简）；后续可换 SSE 流式打字机效果。

## 三、模型选型：「免费豆包」的真实情况

| 选项 | 长期成本 | 接入方式 | 结论 |
|---|---|---|---|
| 豆包（火山引擎方舟 API） | **非免费**：新用户有赠送 tokens，用完按量付费（doubao-lite 约 ¥0.3~0.8/百万 tokens） | OpenAI 兼容 Chat Completions；需注册火山引擎+实名+建 API Key | 便宜好用，但不是"免费" |
| **智谱 GLM-4-Flash** | **永久免费** | OpenAI 兼容，open.bigmodel.cn 注册即得 key | **首选**，中文质量好 |
| 硅基流动 SiliconFlow | 免费档（Qwen2.5-7B、GLM-4-9B 等） | OpenAI 兼容 | 备选 |
| 本地 on-device（MediaPipe LLM / Gemma-2B 等） | 完全免费离线 | 模型打包进 APK（+1~2GB） | 完全离线但中文弱、包体大，备选 |

**建议路线**：网络层写成 `Provider(base_url, api_key, model)` 三元组可配置——
先用 GLM-4-Flash 跑通全流程（零成本），之后想用豆包，在设置页填火山引擎的 key 即可切换，一行代码不用改。

## 四、隐私与「全本地」理念的冲突点

- 云端 LLM 意味着**记账原文和聊天内容会出网**。语音识别在多数国产手机上是本地的，但文本理解必须上云（除非走 on-device）。
- 缓解：设置页明示开关「AI 功能默认关闭」；发送内容仅限单条话术，不带历史账目明细（账目摘要只发统计数字）；不存云端会话。
- 若坚持绝对本地，选 on-device 方案，牺牲质量换隐私。

## 五、落地工作量预估（MVP 一个版本）

| 模块 | 内容 | 新增文件 |
|---|---|---|
| 网络层 | OkHttp 调 OpenAI 兼容接口，Provider 可配置 | `data/LlmClient.kt` |
| 语音入口 | SpeechRecognizer 弹窗 → 文本 | `ui/record/VoiceSheet.kt` |
| 解析落库 | JSON 抽取 + 校验 + 自动建小类 | `util/RecordParser.kt` |
| 聊天页 | 消息列表 + 输入框 + 人设 | `ui/chat/ChatScreen.kt`、`vm/ChatViewModel.kt` |
| 设置扩展 | 命名、Provider/key、开关 | `SettingsScreen.kt` 增量 |

风险：厂商 SpeechRecognizer 可用性差异（无 Google 服务的机型也普遍带厂商引擎）；LLM JSON 偶发不规范（重试+兜底已覆盖）；key 泄漏（存本地 SharedPreferences，不上传仓库）。
